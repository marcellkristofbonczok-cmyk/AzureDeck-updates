# AzureDeck 1.9.10 — Startup detection and full clean reinstall

A background installer helper no longer fails a live player immediately. A live client gets the full 90-second join window; matching account/place replication evidence confirms the join. An exited player with a persistent installer receives a 15-second startup grace period and at least five seconds of exit grace. A unique replacement player child is tracked through a normal process handoff. An installer name alone cannot trigger preflight recovery; visible update/error evidence and a trusted Roblox publisher are required. Earlier name-only false-positive latches are revalidated once; genuine critical-error blocks remain.

Automatic recovery now closes verified Roblox players, releases multi-instance compatibility, waits for an existing updater to finish, and downloads a fresh installer from Roblox's official HTTPS host. Its Roblox Corporation signature is verified before cleanup. AzureDeck then deletes the ENTIRE native Windows %LOCALAPPDATA%\Roblox directory, including Player, Studio installation/settings/cache and other local data. It does not delete %APPDATA%\Roblox. Only Roblox Player is reinstalled. Close Studio first; an open Studio blocks deletion. The exact target is resolved from Windows, independent of environment-variable overrides.

The installer is staged outside Roblox. AzureDeck data and the running manager are protected from overlap. Root junctions and path traversal are rejected; nested links are removed without following outside targets. Locked files, failed deletion or cancellation stop the flow and keep launches blocked. Deleted data cannot be restored by Cancel. Cancelling an already running installer stops waiting and allows its writes to finish.

After the official installer and helpers finish, AzureDeck checks local readiness, restores compatibility, obtains a fresh launch ticket, and retries the interrupted account/selected batch. Accounts outside that batch remain closed. One clean reinstall is allowed per recovery episode; failure does not repeat deletion. Another automatic episode requires a confirmed healthy join plus the existing 30-minute cooldown. Repair now explicitly resets the limit. The default-on option and progress/cancel/recheck controls are under Settings > Launch & recovery.

Validation uses disposable process trees and temporary cleanup folders, including outside-link sentinels. The official installer download/signature is checked without executing it. The user's real Roblox folder is not deleted and live account joins are not exercised during validation. See VALIDATION.md.
